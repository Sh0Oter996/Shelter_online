# 🏚️ Shelter — онлайн

Мультиплеерная версия настольной игры «Shelter»: каждый игрок заходит со своего телефона или компьютера по ссылке, а состояние партии синхронизируется через **Firebase Realtime Database**. Сайт остаётся полностью статическим — без Node.js-сервера, поэтому его можно бесплатно разместить на **GitHub Pages**.

## Быстрый старт

### 1. Проверить интерфейс без Firebase

Игра умеет работать в **локальном режиме** — между вкладками одного браузера. Это не продакшен, но позволяет сразу посмотреть лобби и партию.

Нужен любой статический сервер (ES-модули не работают через `file://`):

```bash
# Node.js 18+
npm run serve
# откройте http://127.0.0.1:4173/?local=1
```

или:

```bash
python -m http.server 4173
```

Откройте `http://127.0.0.1:4173/?local=1`, создайте комнату, затем откройте вторую вкладку с той же ссылкой-приглашением. В локальном режиме каждая вкладка — отдельный игрок.

> ⚠️ Локальный режим работает только между вкладками одного браузера. Для игры с разных устройств подключите Firebase (ниже).

### 2. Подключить Firebase

1. Заполните `firebase-config.js`.
2. Опубликуйте правила из `database.rules.json`.
3. Обновите страницу — вместо экрана настройки появится главный экран.

Подробно — в разделе [Настройка Firebase](#настройка-firebase).

## Как устроен мультиплеер

Архитектура **host-authoritative** (ведущий — авторитет):

```
Игрок 1 ──команда──┐
Игрок 2 ──команда──┼──► Firebase Realtime Database ──► Хост-вкладка
Игрок 3 ──команда──┘         ▲                         (движок игры)
                             │
                   публичное состояние + приватные руки
                             │
              все игроки видят обновления в реальном времени
```

- **Хост** — создатель комнаты. Его вкладка запускает игровой движок, проверяет команды и записывает состояние в базу.
- Остальные игроки отправляют только **намерения**: раскрыть характеристику, проголосовать, применить карту.
- Хост публикует:
  - `state` — публичную проекцию (без чужих секретов и бюллетеней);
  - `hand/{uid}` — приватную руку каждого игрока;
  - `hostState` — полное состояние, доступное только хосту.
- Если хост закрыл вкладку, партия **приостанавливается**. Он может открыть ту же ссылку снова — состояние восстановится из `hostState`. Если хост пропал насовсем, комнату нужно создать заново.
- Хост-режим защищён Web Locks: если открыть две вкладки хоста в одном браузере, движок запустится только в одной, а вторая станет режимом просмотра.

Firebase здесь заменяет сервер: клиенты не могут писать игровое состояние напрямую, а Security Rules не дают читать чужие руки и полное состояние хоста.

## Настройка Firebase

Понадобится аккаунт Google. Бесплатного плана **Spark** достаточно для дружеских партий (актуальные лимиты смотрите на странице тарифов Firebase).

### Шаг 1. Создайте проект

1. Откройте [console.firebase.google.com](https://console.firebase.google.com/).
2. **Add project** → введите имя, например `shelter-online`.
3. Google Analytics можно отключить — для игры он не нужен.
4. Дождитесь создания проекта.

### Шаг 2. Создайте Realtime Database

Важно: нужна именно **Realtime Database**, а не Firestore.

1. В левом меню: **Build → Realtime Database**.
2. **Create Database**.
3. Выберите регион (например, `europe-west1` или `us-central1`).
4. Начните в **locked mode** — правила мы опубликуем отдельно.
5. Скопируйте URL базы. Он выглядит так:

```
https://shelter-online-default-rtdb.europe-west1.firebasedatabase.app
```

Это значение нужно для `databaseURL` в конфиге.

### Шаг 3. Включите анонимный вход

1. **Build → Authentication → Get started**.
2. Вкладка **Sign-in method**.
3. Выберите **Anonymous** → **Enable** → **Save**.

Без этого приложение покажет ошибку `auth/operation-not-allowed`.

### Шаг 4. Зарегистрируйте веб-приложение

1. ⚙️ **Project settings** → **General**.
2. Внизу **Your apps** → иконка `</>` (Web).
3. Введите nickname (например, `shelter-web`) → **Register app**.
4. Скопируйте объект `firebaseConfig`.

Если в нём нет `databaseURL` (так бывает, если база создана позже), добавьте его вручную из шага 2.

### Шаг 5. Заполните `firebase-config.js`

Откройте `firebase-config.js` и подставьте свои значения:

```js
export const firebaseConfig = {
  apiKey: "AIzaSy...",
  authDomain: "shelter-online.firebaseapp.com",
  databaseURL: "https://shelter-online-default-rtdb.europe-west1.firebasedatabase.app",
  projectId: "shelter-online",
  storageBucket: "shelter-online.appspot.com",
  messagingSenderId: "123456789012",
  appId: "1:123456789012:web:abcdef123456"
};
```

`FIREBASE_READY` вычисляется автоматически: пока `apiKey`, `projectId` или `databaseURL` пустые, игра показывает экран настройки.

> **Это нормально, что конфиг виден всем.** `apiKey` веб-приложения Firebase не является секретом. Доступ к данным защищают Security Rules. Никогда не вставляйте в клиентский код сервисный аккаунт (`serviceAccount`, private key) — это уже настоящий секрет.

### Шаг 6. Опубликуйте Security Rules

**Через консоль (проще):**

1. **Realtime Database → Rules**.
2. Удалите содержимое редактора.
3. Вставьте весь JSON из `database.rules.json` (он же — в разделе [Security Rules](#security-rules)).
4. **Publish**.

**Через Firebase CLI (если удобнее):**

```bash
npm install -g firebase-tools
firebase login
firebase use --add          # выберите свой проект
firebase deploy --only database
```

`firebase.json` уже указывает на `database.rules.json`, поэтому команда применит именно эти правила.

Проверить, что правила применились, можно во вкладке **Rules** — там будет ваш JSON, а не стандартные `"auth != null"`.

### Шаг 7. Проверьте облако

1. Запустите статический сервер: `npm run serve`.
2. Откройте `http://127.0.0.1:4173/`.
3. Создайте комнату.
4. Откройте ссылку-приглашение **в другом браузере или профиле** и войдите вторым игроком.

> В одном браузере Firebase использует один анонимный UID на все вкладки. Поэтому две вкладки одного профиля — это **один и тот же игрок**. Для теста мультиплеера берите разные браузеры (Chrome + Firefox), режим инкогнито или разные устройства. В локальном режиме (`?local=1`) ограничение другое: вкладки как раз считаются разными игроками.

    ".write": false,

### Что именно защищают правила

| Путь | Чтение | Запись | Зачем |
|---|---|---|---|
| `/` | запрещено | запрещено | Всё начинается с закрытого корня |
| `rooms/{code}/meta` | любой авторизованный | создатель (при создании) и хост | Нужно, чтобы проверить существование комнаты и войти; секретов здесь нет |
| `rooms/{code}/members` | участники и хост | сам игрок: вход/удаление — в лобби, обновление своей записи; хост — всегда | Игрок может войти только в лобби; во время игры нельзя удалить себя из участников; хост может удалять участников |
| `rooms/{code}/presence/{uid}` | участники | только сам игрок | Онлайн-статус и heartbeat; `onDisconnect` убирает запись |
| `rooms/{code}/state` | участники | только хост | Публичная проекция игры |
| `rooms/{code}/hand/{uid}` | сам игрок и хост | только хост | Приватная рука: значения, карта действия, условие |
| `rooms/{code}/hostState` | только хост | только хост | Полное состояние со всеми секретами |
| `rooms/{code}/commands` | только хост | игрок — свою команду, хост — удаление | Очередь намерений; `uid` внутри команды обязан совпадать с `auth.uid` |
| `rooms/{code}/errors/{uid}` | сам игрок и хост | только хост | Приватные сообщения об отклонённых действиях |

Дополнительно:

- Создать комнату можно только с `meta.hostUid === auth.uid`.
- Код комнаты — 4–6 символов (клиент генерирует 6 цифр).
- Имя — строка от 1 до 20 символов.
- `status` может быть только `lobby`, `playing` или `ended`.
- Удалить команду может только хост; игрок не может подделать `uid` в команде.
- Удалять данные комнаты может только её хост.

### Чего правила не делают

- **Не защищают от хоста.** Хост — это игрок, и его вкладка хранит полное состояние: он технически может открыть DevTools и увидеть чужие карты. Это неизбежно для статического сайта без сервера. Для дружеской игры это приемлемо; для турнира нужен сервер/Cloud Functions.
- **Не ограничивают частоту запросов.** Код комнаты можно перебирать; 6 цифр и случайная генерация снижают риск, но не исключают его. Не публикуйте код в открытых чатах.
- **Не дают полноценной аутентификации.** Anonymous Auth — это идентификатор браузера, а не аккаунт. Очистка данных сайта = потеря места в комнате.
- **Не шифруют данные на уровне приложения.** Трафик идёт по HTTPS, но данные видны администратору проекта Firebase.

Для дополнительной защиты можно:

- включить **Firebase App Check** (reCAPTCHA v3) — ограничит автоматизированные запросы;
- ограничить API key по HTTP referrer в Google Cloud Console (не обязательно для RTDB, но снижает злоупотребление);
- добавить Cloud Function для очистки старых комнат (потребует Blaze-план).

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub (публичный — на бесплатном плане; приватный Pages доступен на платных тарифах).
2. Загрузите файлы проекта в корень репозитория. Не коммитьте `node_modules/`, `.chrome-e2e-profile/`, `test-results/` — они уже в `.gitignore`.

```bash
git init
git add .
git commit -m "Shelter online"
git branch -M main
git remote add origin https://github.com/<логин>/<репозиторий>.git
git push -u origin main
```

3. Проверьте, что `firebase-config.js` заполнен (или заполните после публикации).
4. В репозитории: **Settings → Pages**.
5. **Build and deployment → Source**: `Deploy from a branch`.
6. **Branch**: `main`, папка `/ (root)` → **Save**.
7. Через 1–2 минуты сайт будет доступен по адресу:

```
https://<ваш-логин>.github.io/<название-репозитория>/
```

Файл `.nojekyll` уже добавлен — GitHub Pages не будет пытаться обрабатывать проект через Jekyll.

### Добавьте домен GitHub Pages в Firebase Auth (рекомендуется)

Anonymous Auth обычно работает без этого, но список доменов стоит обновить, чтобы не поймать `auth/unauthorized-domain` при будущих способах входа:

1. **Authentication → Settings → Authorized domains**.
2. **Add domain** → `<ваш-логин>.github.io`.
3. Сохраните.

Для локальной проверки `localhost` и `127.0.0.1` уже разрешены Firebase по умолчанию.

### Важно для Firebase

- Все пути в проекте относительные (`js/main.js`, `styles.css`), поэтому сайт работает и в подпапке `/<repo>/`.
- Добавлять домен GitHub Pages в Firebase Auth для Anonymous Auth обычно **не требуется**: список Authorized domains нужен прежде всего для OAuth-редиректов. Но добавить `<логин>.github.io` в **Authentication → Settings → Authorized domains** полезно на будущее (см. ниже).
- Если вы позже поменяете `firebase-config.js`, GitHub Pages обновит файл после нового коммита. Пользователям может понадобиться обновить страницу с очисткой кеша.

## Как играть

Для обсуждения решений используйте голосовой звонок или чат отдельно: в игре есть журнал событий, но нет встроенного голосового чата.

### Лобби

- Хост вводит имя, выбирает сценарий и число выживших, создаёт комнату.
- Получает **6-значный код** и ссылку-приглашение. Кнопки копирования — рядом.
- Остальные открывают ссылку, вводят имя и попадают в лобби.
- Хост видит список игроков, может удалить офлайн-участника кнопкой `✕`.
- Для старта нужно от 4 до 15 игроков.
- Раунды и квоты голосований рассчитываются автоматически, чтобы к финалу осталось выбранное число выживших.

### Раунд

1. Все игроки видят историю бункера. Хост нажимает «Войти в бункер и начать раунд 1».
2. Игроки ходят по очереди. В свой ход игрок видит кнопки раскрытия в своей карточке и выбирает одну характеристику.
3. Профессия и пол открыты с начала игры. Остальные значения видны только владельцу, пока он их не раскроет.
4. В свой ход можно сначала активировать секретную карту действия, затем всё равно нужно раскрыть характеристику.
5. Когда все живые игроки сделали ход, начинается следующий раунд или голосование.

### Голосование

- Голосование **последовательное**: в каждый момент голосует один игрок, остальные видят прогресс. Так бюллетени остаются тайными.
- Голос нельзя изменить.
- После всех голосов показываются результаты. Хост нажимает «Продолжить», чтобы применить изгнание.
- Если голоса разделились:
  - при равенстве среди лидеров и наличии выбывших — **решающий голос выбывших** (совещаются, засчитывается первый нажатый);
  - если выбывших нет — переголосование только среди лидеров.

### Хост

- Только хост начинает игру, начинает раунд, продолжает после голосования и перезапускает партию.
- Если игрок отключился и не отвечает более двух минут, хост может **пропустить его ход или голос** (кнопка появляется в панели ожидания).
- Хост должен держать вкладку открытой. При закрытии игра встаёт на паузу; после повторного открытия ссылки состояние восстановится.
- В лобби кнопка «Выйти» у хоста **закрывает комнату для всех**.

### Финал

Когда в бункере остаётся нужное число выживших, игра считает ресурсы, открытые комнаты, сработавшие условия и показывает концовку. Хост может нажать «Сыграть снова» — все вернутся в лобби этой же комнаты.

## Данные в базе

```
rooms/{CODE}/
├── meta/
│   ├── hostUid          uid создателя
│   ├── status           lobby | playing | ended
│   ├── createdAt        timestamp
│   ├── updatedAt        timestamp
│   ├── playerCount      число игроков
│   ├── scenarioId       id сценария или random
│   └── survivors        сколько должно выжить
├── members/{uid}/
│   ├── name
│   ├── joinedAt
│   └── isHost
├── presence/{uid}/
│   ├── online
│   ├── at               последний heartbeat
│   └── name
├── state/               публичная проекция (см. buildPublicState)
├── hand/{uid}/          приватная рука игрока
│   ├── player           все значения, карта действия, условие
│   └── flags            чей ход / чей голос
├── hostState/           полное состояние движка (только хост)
├── commands/{pushId}/   очередь команд
│   ├── uid
│   ├── type
│   ├── payload
│   └── at
└── errors/{uid}/        приватные ошибки действий
    ├── text
    └── at
```

Публичное состояние намеренно **не содержит**:

- значения нераскрытых характеристик;
- чужие карты действий и условий;
- отдельные бюллетени (только итоговый подсчёт после голосования).

Приватная рука содержит полную карточку игрока. `hostState` содержит всё, включая бюллетени и карты, и доступен только хосту.

## Ограничения и безопасность

1. **Хост — доверенная сторона.** Он видит все секреты. Это осознанный компромисс ради статического сайта.
2. **Один игрок = один браузерный профиль.** В Firebase две вкладки одного профиля — один и тот же UID. Используйте разные устройства/браузеры.
3. **Anonymous Auth.** Очистка данных сайта или смена браузера = новый игрок. Старое место останется в партии; хост сможет пропустить ход.
4. **Хост должен быть онлайн.** Если хост закрыл вкладку, партия ждёт. Это не серверная игра с бесшовным failover. Хост-режим держится только в одной вкладке (Web Locks); вторую вкладку хоста можно использовать для просмотра, но после закрытия основной вкладки её нужно перезагрузить, чтобы она подхватила хост-режим.
5. **Коды комнат.** 6 цифр — это ключ доступа. Любой, кто знает код, может войти в лобби (если игра ещё не началась). Не публикуйте код публично.
6. **Нет модерации.** Имена и «придумай сам» значения не фильтруются, кроме длины и экранирования HTML. Играйте с теми, кому доверяете.
7. **Лимиты Firebase.** Каждое действие перезаписывает публичное состояние и все руки. Для 4–15 игроков это нормально, но следите за квотами на бесплатном плане.
8. **Старые комнаты не удаляются автоматически.** В лобби хост может закрыть комнату. Брошенные комнаты можно удалить вручную в консоли Firebase (Realtime Database → данные → удалить `rooms/{code}`). При желании добавьте Cloud Function для очистки.
9. **Передачи роли хоста нет.** Если хост не вернётся, партию не продолжить — можно только создать новую комнату.

## Решение проблем

### «Нужно подключить облако»

`firebase-config.js` не заполнен или `FIREBASE_READY === false`. Нужны минимум `apiKey`, `projectId` и `databaseURL`. После заполнения обновите страницу.

### `auth/operation-not-allowed`

Не включён Anonymous Auth. **Authentication → Sign-in method → Anonymous → Enable**.

### `PERMISSION_DENIED` при создании/входе

- Правила не опубликованы или опубликованы не из `database.rules.json`.
- Неверный `databaseURL` (другой проект/регион).
- Комната уже удалена.
- Проверьте вкладку **Rules** в консоли Firebase и нажмите **Publish** ещё раз.

### `Firebase: Error (auth/invalid-api-key)`

Скопирован неверный `apiKey` или конфиг от другого проекта. Перекопируйте `firebaseConfig` из **Project settings → Your apps**.

### Приглашение открывается, но пишет «Вы ещё не в этой комнате»

Вы не входили в эту комнату ранее, а игра уже началась (или хост вас удалил). Попросите хоста создать новую комнату или вернуть вас в лобби.

### Хост «пропал», игра не идёт

Хост закрыл вкладку. Попросите его открыть ту же ссылку — состояние восстановится. Если он не вернётся, комнату не продолжить.

### Две вкладки — один игрок

Это Firebase Anonymous Auth: UID общий на профиль браузера. Для теста используйте разные браузеры/профили или локальный режим (`?local=1`), где вкладки — разные игроки.

### Локальный режим не видит комнату из другой вкладки

- Обе вкладки должны быть на одном origin (`http://127.0.0.1:4173`), не `file://`.
- Обе должны иметь `?local=1`.
- Очистка сайта удаляет локальную базу.

### GitHub Pages отдаёт 404

- Проверьте **Settings → Pages**: ветка `main`, папка `/ (root)`.
- Подождите 1–2 минуты после пуша.
- Ссылка должна быть `https://user.github.io/repo/`, а не `.../repo/index.html`.
- Убедитесь, что файлы лежат в корне репозитория, а не во вложенной папке.

### Firebase SDK не загружается

`gstatic.com` может блокироваться сетью/расширением. Откройте консоль браузера — будет ошибка импорта. Попробуйте другую сеть или VPN. Приложение при этом может работать в локальном режиме.

## Тесты

### Движок

```bash
npm test
```

Проверяется: полная партия до финала, отсутствие утечек скрытых значений, тайна бюллетеней, карты действий, нормализация данных RTDB, перезапуск, пропуск AFK-хода/голоса, а также совпадение правил в README и `database.rules.json`.

### Сквозной тест в браузере

Нужен установленный Google Chrome и запущенный сервер. Для `tools/e2e.mjs` нужен Node.js 22+ (глобальный `WebSocket`):

```bash
npm run serve
# в другом терминале
node tools/e2e.mjs
```

Тест открывает 5 вкладок через Chrome DevTools Protocol (хост, три игрока и лишний участник для проверки удаления), создаёт комнату, входит игроками, удаляет лишнего, играет партию до финала, проверяет перезагрузку хоста и игрока посреди игры, перезапуск, выход игрока и закрытие комнаты. Скриншоты сохраняются в `test-results/`.

Переменные окружения:

- `CHROME` — путь к Chrome (по умолчанию `C:\Program Files\Google\Chrome\Application\chrome.exe`);
- `BASE_URL` — адрес сервера (по умолчанию `http://127.0.0.1:4173`);
- `CDP_PORT` — порт отладки (по умолчанию `9333`).

Если Chrome запускается в песочнице и падает с ошибкой доступа к IPC — это ограничение окружения, а не игры; запустите тест вне песочницы.

## Что изменилось по сравнению с локальной версией

- Игра стала **онлайн-комнатой**: игроки заходят по коду/ссылке со своих устройств.
- Имена и число игроков определяются фактически вошедшими участниками (4–15), а не задаются заранее списком.
- Своя карточка видна всегда, а не только в свой ход; нераскрытые значения видит только владелец.
- Хост управляет началом раунда, продолжением после голосования и перезапуском.
- Голосование последовательное и анонимное; результаты синхронизируются.
- Карта «Кража багажа» выбирает первый доступный предмет автоматически — иначе пришлось бы раскрывать чужой багаж до применения карты.
- Раунды и квоты голосований рассчитываются автоматически от числа игроков и выживших.
- Добавлены: удаление игроков из лобби, пропуск AFK-хода/голоса хостом, presence-статусы, восстановление после перезагрузки, журнал и защита секретов через Security Rules.
- Старые JS-модули (`config.js`, `gameplay.js`, `setup.js`, `state.js`, `utils.js`) сохранены в `legacy/` для справки. Новая версия их не подключает.
